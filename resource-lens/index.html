Free PhpStorm plugin

Model attribute names that are right the first time.

Resource Lens completes, links and checks Eloquent model attribute names in Laravel admin panel resources built with Filament 4 and 5. It reads your migrations and model classes inside PhpStorm, so a column name typed by you or written by an AI assistant is checked against the model before you open the browser.

Install in PhpStorm When it stays silent

What the plugin does

Four features, all read from your own project's code. No setup, no server, no account.

Completion
Model attributes and relationships inside TextInput::make('…'), TextColumn::make('…'), Select::make('…') and the other form field, table column, infolist entry and filter constructors. It completes the first segment of a dotted name.
Go to declaration
Ctrl-click (Cmd-click on macOS) a name to jump to where it is declared: the migration column, @property tag, cast, fillable or $appends entry, accessor, or relationship method.
Unknown attribute warning
On core table columns and infolist entries whose name matches no attribute or relationship of the model, checking every segment of a path such as author.name. It stays silent whenever it cannot be certain (see below).
Rename and gutter links
Renaming an accessor or relationship method updates the make('…') names that use it. A gutter icon links each Resource to its model and each model back to its Resources.

Install

PhpStorm 2025.3 or newer, on a Laravel project with Filament 4 or 5.

  1. Open Plugins

    In PhpStorm, open Settings (Preferences on macOS) and choose Plugins, then the Marketplace tab.

  2. Search

    Search for "Resource Lens", click Install, and restart the IDE if it asks.

  3. Open a Resource

    Open a Resource, form schema or table class and press Ctrl+Space inside a make('') string.

The gutter icon can be switched off in Settings | Editor | General | Gutter Icons, and the warning in Settings | Editor | Inspections | Resource Lens.

When the warning stays silent

A wrong warning on correct code teaches people to switch the check off, so Resource Lens says nothing unless it is certain.

The warning checks these classes exactly (not subclasses): TextColumn, IconColumn, ImageColumn, ColorColumn, ToggleColumn, TextInputColumn, SelectColumn, CheckboxColumn, TextEntry, IconEntry, ImageEntry, ColorEntry and KeyValueEntry. It says nothing when:

  • The component is a form field or a filter (virtual fields such as password_confirmation are legitimate), or a subclass or plugin column.
  • The chain after make() gives the state another source: state, getStateUsing, counts, exists, avg, sum, min, max, view, rowIndex, default, placeholder.
  • The name ends in _count or _exists, or is not a plain dotted name.
  • The component sits inside a repeater, a Builder block, a filter's schema, ->relationship(), ->statePath(), ->record(), ->model(), ->records(), or a table with its own ->query().
  • The table calls modifyQueryUsing, or the Resource or one of its parent classes declares getEloquentQuery.
  • The component is built outside a columns(), components() or schema() array.
  • The model cannot be resolved with certainty, or a class other than a Resource (a relation manager, a Livewire component) also configures the table or schema.
  • The model's columns are not fully known: its migrations use macros, helpers, computed Blueprint methods or raw SQL. Docblock @property tags add names to completion but never make the column list complete.

Migrations are read from every database/migrations directory in the project, except under vendor/. Duplicate model classes written by laravel-ide-helper are ignored.
